Classes

AffineForm

The normal form of a linear expression: constant + Σ coefficient · variable, with variables in a fixed order and no zero coefficients. Two linear expressions denote the same function exactly when their affine forms are equal, so x + y and y + x normalise to equal values even though the expressions themselves differ.

AffineForms

Arithmetic and analysis over AffineForm and Interval.

Anchoring

Building points out of plain values and quantities: start + dwell. These cannot be generic operators, because no operand is a Point<T, TDelta> and generic code does not know how a TDelta is added to a T; so each point type declares its own T + Quantity<TDelta> operators beside its projection, in terms of these.

BinaryVariable

A variable that is either 0 or 1. It is both a linear expression (its 0/1 value) and a boolean expression (true exactly when it is 1), so it can be summed and scaled as well as combined with &, | and !.

BooleanConstant

A fixed truth value.

BooleanOperators

Logical operators over IBooleanExpression. As with the linear operators, these only build data; normal forms are computed later, when a model is encoded for a solver.

Column

A variable as a MILP solver sees it: with native bounds. The bounds are those the problem's top-level constraints state outright (x <= 10), or the variable's intrinsic ones.

Comparison

Conjunction

Constant

ContinuousVariable

DateTimeProjection

DeepRecursion

Expressions are as-written trees, so folding + or & over a long sequence makes a tree as deep as the sequence is long. Recursive passes stay natural by continuing on a fresh stack whenever the current one is nearly exhausted, instead of overflowing. Public so that solver backends which walk expressions themselves can do the same.

Disjunction

Holds exactly when at least one side holds.

EncodingOptions

Settings for lowering a problem to a MilpProblem.

Equivalence

Holds exactly when both sides have the same truth value.

Evaluation

Reads expressions off a solution. Any expression can be read, not just variables.

Feasible

A solution that satisfies the constraint but is not proven best, typically because a limit was reached.

Formatting

Renders expressions the way they were written, for logs, error messages and code review: (departureA + 120 <= departureB) | (departureB + 120 <= departureA).

GuardedRow

Expression <= 0 (or == 0) whenever every guard holds. With no guards the row holds unconditionally.

Implication

Holds unless the antecedent holds and the consequent does not.

IndicatorProblem

A problem with its logic encoded but no big-M in sight: bounded columns, a linear objective, and rows that are linear except for being guarded by literals. This is the natural input for solvers with indicator constraints (Gurobi) or half-reified constraints (CP-SAT), and the half-way point on the road to a MilpProblem.

IndicatorProblems

IndicatorSolver

Turns any indicator backend into a solver for full problems: encode the logic, solve, then hide the auxiliary variables and snap whole-number variables to whole numbers. No big-M is involved.

Infeasible

IntegerVariable

A variable ranging over the whole numbers.

LinearNormalisation

The pass that flattens an as-written linear expression into its AffineForm.

LinearOperators

Arithmetic and comparison operators over ILinearExpression. Operators only build data: a + b is new Sum(a, b), nothing is simplified or flattened here.

LinearRow

The linear constraint LowerBound <= Σ coefficient · variable <= UpperBound.

Literal

Maximisation

MilpEncoding

Lowers a problem in pure steps: normalise and encode the logic with guarded rows, giving an IndicatorProblem; then propagate bounds and relax the guards with big-M values derived from them, giving a MilpProblem.

MilpProblem

A problem lowered to a plain mixed-integer linear programme: bounded columns, linear rows and a linear objective. This is all a MILP backend ever needs to understand.

MilpProblems

MilpSolver

Turns any MILP backend into a solver for full problems: encode, relax the guards with derived big-M values, solve, then hide the auxiliary variables and snap whole-number variables to whole numbers.

Minimisation

Find an assignment that makes the objective as small as possible while the constraint holds.

ModellingException

Thrown when a model cannot be given a meaning: clashing variable names, non-finite coefficients, or a big-M value that cannot be derived because a variable lacks bounds.

Negation

Occurrences

Optimal

A solution that is proven to be the best possible.

PointOperators

The algebra of positions: point - point is a quantity, point ± quantity is a point, and points compare with points. There is deliberately no point + point and no scaling.

Point<T, TDelta>

A linear expression read as a position of type T: a date-time, a chainage. Points can be compared and shifted by quantities of TDelta, and the difference of two points is such a quantity; adding or scaling points does not type-check.

Problem

Factory functions that read like the mathematics: Problem.Minimise(cost, subjectTo: constraint).

Product

A linear expression scaled by a fixed coefficient. There is deliberately no product of two expressions: non-linear terms are unrepresentable.

QuantityOperators

The algebra of amounts. Every operator reduces to the corresponding operator on the underlying linear expressions, after bringing the right-hand side into the left-hand side's projection.

Quantity<T>

A linear expression read as an amount of type T: a duration, a length, a cost. Quantities can be added, subtracted, scaled and compared, with each other and with plain T values.

Satisfaction

Solution

An assignment of values to a problem's variables, as found by a solver.

SolveResults

SolverOptions

Sum

SystemTimeOperators

SystemTimeVariables

Interfaces

IBooleanExpression

A truth-valued expression over linear comparisons and binary variables. The cases are BooleanConstant, Comparison, Negation, Conjunction, Disjunction, Implication, Equivalence and BinaryVariable. Like linear expressions, boolean expressions are plain data kept exactly as written.

IIndicatorBackend

A solver with indicator or half-reified constraints: it takes rows guarded by literals as they stand, so nothing is relaxed with a big-M and no bounds are needed for the encoding.

ILinearExpression

A real-valued expression that is linear (strictly: affine) in its variables. The cases are Constant, Sum, Product and the IVariable records. Expressions are plain data, kept exactly as written; all interpretation (normalisation, bounds, encoding, evaluation) happens in later passes.

IMilpBackend

A solver for plain mixed-integer linear programmes.

IPointProjection<T, TDelta>

The projection of a type whose values are positions rather than amounts (date-times, not durations). Positions cannot be added or scaled, but the difference between two of them is an amount, of type TDelta.

IProblem

An optimisation problem: a single constraint, optionally with an objective. There is no list of constraints, because a list would only duplicate what & already means; conjoin a collection with AllOf(). The cases are Satisfaction, Minimisation and Maximisation.

IProjection<T>

How values of a domain type lie along the solver's number line: for example durations measured in seconds, or date-times measured in seconds since some origin. A projection must be affine and increasing (equal steps in T are equal steps in number, and later means larger). That is what lets expressions under different projections of the same type be combined: the conversion between any two is recovered from where they send zero and one. Implement projections as records, so that equal projections compare equal.

ISolveResult

The outcome of solving a problem. The cases are Optimal, Feasible, Infeasible, Unbounded and Unknown.

ISolver

Anything that can solve a problem. This is the seam along which solvers are swapped: a backend that understands boolean structure natively (such as an SMT solver) implements it directly, while MILP backends implement the much smaller IMilpBackend and are wrapped in a MilpSolver.

IVariable

A decision variable: a name and a kind, nothing more. Variables are values, so two variables of the same kind and name are the same variable. Bounds are not part of a variable; they are ordinary constraints (0 <= x & x <= 10), which the encoder recognises and passes to the solver as native bounds.
